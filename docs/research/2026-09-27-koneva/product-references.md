# Riset divisi produk dan teknologi KONEVA

Tanggal pemeriksaan: 27 September 2026. Ini riset web primer, bukan audit implementasi repository atau bukti kelayakan produksi. Estimasi effort dan target penerimaan di bawah adalah usulan PM; perlu disesuaikan setelah gap audit. Tidak ada email/WhatsApp/produksi yang disentuh.

## Kesimpulan untuk PM

Nilai jual terbaik untuk Pelajar/UMKM: layanan terkelola yang mudah dipasang, status kirim jelas, integrasi tidak menggandakan transaksi, kontrol penggunaan transparan, dan dukungan berbahasa Indonesia. Jangan menjual akses library atau fitur kirim pesan sebagai pembeda tunggal: WAHA kini memasukkan semua fitur bekas Plus ke Core gratis sejak versi 2026.6.1. [WAHA perubahan Plus](https://waha.devlike.pro/docs/how-to/waha-plus/).

Jalur Baileys tetap membawa risiko platform. MIT memberi izin penggunaan software dengan kewajiban notice, bukan izin menggunakan WhatsApp di luar ketentuan platform. README Baileys mengatakan tidak terafiliasi WhatsApp, tidak mendukung pelanggaran ToS, dan discourages spam, bulk maupun automated messaging. Maka jangan mengemas warm-up sebagai anti-ban atau menjanjikan nomor aman. [Lisensi Baileys](https://github.com/WhiskeySockets/Baileys/blob/master/LICENSE), [disclaimer upstream](https://github.com/WhiskeySockets/Baileys/blob/master/README.md#disclaimer).

## Delapan adopsi prioritas

| Prioritas / divisi | Usulan KONEVA dan manfaat | Referensi primer | Effort / risiko | Acceptance criteria usulan |
| --- | --- | --- | --- | --- |
| P0 Produk + Trust | Alur persetujuan penerima, daftar opt-out dan penghentian kirim, peninjauan penyalahgunaan. Tampilkan status kanal tidak resmi saat onboarding. Pembatasan kirim untuk mengontrol penggunaan dan biaya, bukan menghindari deteksi. | [Twilio WhatsApp API](https://www.twilio.com/docs/whatsapp/api) menjelaskan opt-in dan penghormatan opt-out; ini pola kanal resmi yang diadaptasi sebagai perlindungan produk, bukan klaim bahwa Baileys menjadi disetujui. | Sedang / perubahan alur pelanggan; tidak menghilangkan risiko platform. | Penerima opt-out ditolak dari API, jadwal, antrean, dan auto-reply; penghentian workspace menghalangi semua jalur outbound; audit mencatat keputusan tanpa isi pesan sensitif. |
| P0 Backend + QA | Jaminan idempotensi API kirim dan kontrak webhook: event ID stabil, attempt ID berbeda, HMAC + timestamp, retry berjeda, antrean gagal dan replay. Mencegah notifikasi pesanan/invoice ganda saat koneksi putus. | [WAHA Events](https://waha.devlike.pro/docs/how-to/events/) menyediakan HMAC, timestamp dan retry; [Stripe webhooks](https://docs.stripe.com/webhooks) mengantisipasi duplikasi, retry dan urutan berbeda; [Stripe idempotency](https://docs.stripe.com/api/idempotent_requests). | Sedang–besar / tidak boleh menjanjikan exactly-once delivery jaringan. | 10 permintaan paralel berkunci sama menghasilkan satu job; payload beda dengan key sama ditolak; restart tidak kehilangan job; webhook retry memakai event ID sama; replay tidak menggandakan efek pada contoh consumer; timeout ambigu tidak otomatis mengirim ulang tanpa rekonsiliasi. |
| P0 Infra + Finance | Meter biaya per nomor dan observability: RAM/CPU p50/p95, reconnect, panjang/umur antrean, kegagalan webhook, latensi penerimaan API hingga status kirim, storage per tenant. Ini dasar harga yang nyata. | [WAHA observability](https://waha.devlike.pro/docs/how-to/observability/) menyediakan Prometheus dan status sesi; [WAHA FAQ](https://waha.devlike.pro/docs/overview/faq/) menunjukkan kebutuhan resource berbeda menurut engine dan jumlah sesi. | Sedang / label metrik jangan membocorkan nomor atau membuat cardinality tak terkendali. | Pengamatan pilot 7–14 hari; biaya idle dan aktif dipisah; headroom dicatat; benchmark sintetis diberi label; laporan kapasitas KONEVA tidak menyalin angka WAHA sebagai hasil ukur sendiri. |
| P1 UX + Developer Experience | Onboarding bertahap: simulasi tanpa nomor → API key → contoh request → webhook demo → QR dengan persetujuan → uji ke penerima yang telah setuju. Tampilkan alasan gagal dan tindakan berikutnya. | [Twilio Sandbox](https://www.twilio.com/docs/whatsapp/sandbox) memisahkan testing dan produksi serta membatasi penerima pada peserta sandbox; [WAHA Sessions](https://waha.devlike.pro/docs/how-to/sessions/) memberikan lifecycle sesi. | Sedang / simulasi wajib diberi label agar tidak dikira bukti kirim nyata. | Lima pengguna pilot mampu menyelesaikan simulasi tanpa bantuan; target median <10 menit adalah hipotesis; tidak ada pengiriman nyata otomatis dari demo; QR expired/reconnect/logout memiliki penjelasan dan pemulihan. |
| P1 Product + Billing | Halaman paket dan pemakaian menyatakan jumlah nomor, kuota, periode reset, media/storage, retensi log, support, serta perilaku saat kuota habis. Peringatan 70/90/100% per periode dan hard cap default, tambahan pemakaian harus dipilih. | [Stripe billing alerts](https://docs.stripe.com/api/billing/alert) memodelkan peringatan ketika meter melewati ambang. Persentase dan hard cap adalah usulan KONEVA. | Kecil–sedang / jangan menyamakan alert OTP internal dengan kuota pesan pelanggan. | Counter dashboard sesuai ledger; retry dedup tidak menambah hitungan; reset diuji; aturan kuota untuk gagal/diterima/delivered ditulis; invoice manual sesuai paket yang dipilih; tanpa tagihan tambahan tersembunyi. |
| P1 Backend + Release | Matriks fitur dengan status diuji/beta/tidak didukung, pin versi engine, canary dan rollback. Hindari mengiklankan status/profile/media sebelum bukti WA nyata. | [WAHA engine matrix](https://waha.devlike.pro/docs/how-to/engines/) mencatat perbedaan kemampuan engine; [Baileys README](https://github.com/WhiskeySockets/Baileys/blob/master/README.md) memperingatkan breaking changes v7. | Sedang / pin tidak menghilangkan perubahan upstream WhatsApp. | Setiap fitur publik punya bukti, tanggal, versi dan keterbatasan; upgrade melewati suite kontrak dan canary bernomor uji yang diizinkan; rollback session compatibility didokumentasikan. |
| P1 Growth + Customer Success | Jual solusi kecil: notifikasi pesanan, pengingat janji yang disetujui, dan status layanan pelanggan. Sediakan starter Node/PHP dan panduan webhook dalam Bahasa Indonesia; hindari mengejar banyak fitur broadcast. | [Twilio Sandbox](https://www.twilio.com/docs/whatsapp/sandbox) memberi contoh appointment reminder dan order notification; [Evolution API](https://github.com/evolution-foundation/evolution-api) menunjukkan integrasi CRM/automation sebagai nilai ekosistem. | Kecil–sedang / nilai pelanggan masih hipotesis, bukan bukti pasar. | Wawancara 5 UMKM + 5 pelajar; 3 integrasi nyata pilot dengan persetujuan; ukur waktu integrasi, dukungan menit/akun, dan niat membayar; contoh yang sama bisa diuji offline. |
| P2 Architecture + Strategy | Siapkan batas adapter provider sehingga nantinya pelanggan bisa memilih Cloud API resmi; pisahkan capability, status, dan model harga setiap jalur. Cukup desain kontrak dahulu. | [Evolution API](https://github.com/evolution-foundation/evolution-api) mendukung Baileys dan WhatsApp Cloud API melalui arsitektur multi-provider. | Besar jika diimplementasikan / jangan menjanjikan perpindahan nomor atau kesetaraan fitur otomatis. | Dokumen adapter menjabarkan auth, template, webhook, billing, capability dan migrasi; tidak ada auto-fallback antar-provider yang berisiko kirim ganda; Cloud API baru dinyatakan didukung setelah integrasi dan verifikasi tersendiri. |

## Urutan eksekusi PM

Sesudah Claude menyelesaikan alert OTP: review independen perubahan OTP, audit celah pause/suspend seluruh jalur kirim, inventaris status reliability yang sudah ada, ukur biaya pilot, lalu lakukan tes harga. Dokumen ini tidak menyimpulkan fitur rekomendasi belum ada: gap audit diperlukan agar tim tidak membangun ulang fungsi yang sudah tersedia.
